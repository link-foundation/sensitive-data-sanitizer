## Existing components

- npm's native resolver and registry audit work against a committed lockfile. npm-check-updates can discover new direct majors. Registry dist-tags still need to be compared with the locks for transitive packages. [npm audit and lockfile behavior](https://docs.npmjs.com/cli/audit/) · [npm-check-updates](https://github.com/raineorshine/npm-check-updates)
- Deno's supported reproducible workflow is `deno ci`. `deno install --frozen=false` updates the graph before CI verifies it. [Deno dependency management](https://docs.deno.com/runtime/packages/)
- uv compiles a complete, hash-pinned requirements file without installing the NLP stack to discover versions. pip-audit can audit that resolved graph. [uv requirements compilation](https://docs.astral.sh/uv/pip/compile/) · [pip-audit](https://github.com/pypa/pip-audit)
- Dependabot already manages grouped updates in this repository. Renovate also supports package managers and inline dependency extraction when an upstream ecosystem has no native manifest. [Dependabot options](https://docs.github.com/en/code-security/dependabot/working-with-dependabot/dependabot-options-reference) · [Renovate custom managers](https://docs.renovatebot.com/modules/manager/regex/)

## Migration decisions

- `command-stream` 3 removes terminal and recording dependencies from its default installation. The sanitizer uses the shell tag and `command-stream/execa`. It does not call the moved PTY or recording APIs. Browser Commander still declares the 2.x range, so development installs retain a separate 2.x graph. [Command Stream 3 release](https://github.com/link-foundation/command-stream/releases/tag/js-v3.0.0) · [Browser Commander report](https://github.com/link-foundation/browser-commander/issues/193)
- `lino-objects-codec` 1.0.0 keeps the existing codec integration and requires Node 26.13.1 and npm 12.2.2 or later. The project now uses Node 26.13.1 and npm 12.2.3 and has a major changeset for the Node support change. Node, Bun and Deno support the native `RegExp.escape` used by the NER vocabulary builder and changeset package matcher in place of two local implementations. Lino i18n still declares a separate 0.9 codec range. [Codec 1 release](https://github.com/link-foundation/lino-objects-codec/releases/tag/js_v1.0.0) · [Lino i18n report](https://github.com/link-foundation/lino-i18n/issues/45)
- CPython stays on its latest 3.14 patch because current Presidio publishes `Requires-Python: >=3.11,<3.15`, plus caps on NumPy and preshed. Prior CI reached a native failure in `spacy.load("en_core_web_sm")` from the constrained 3.15 graph. Use a hash-locked install and load the actual model when retesting. [Presidio metadata](https://pypi.org/pypi/presidio-analyzer/2.2.366/json) · [Upstream reproduction](https://github.com/data-privacy-stack/presidio/issues/2431#issuecomment-6673100519)
- Java uses current Temurin 21 with a matching Gradle runtime. The generated project uses Gradle 8.14.3, Android Gradle Plugin 8.13.0 and Android SDK API 36. A Java 27 migration would require a Gradle 9 migration outside the current Capacitor template. Setup Java 6.3 makes annotations opt-in, so the workflow explicitly keeps the problem matcher. [Latest Temurin 21](https://github.com/adoptium/temurin21-binaries/releases/latest) · [Gradle Java matrix](https://docs.gradle.org/current/userguide/compatibility.html#java_runtime) · [Capacitor 8 migration](https://capacitorjs.com/docs/updating/8-0) · [Setup Java 6.3 release](https://github.com/actions/setup-java/releases/tag/v6.3.0)
- Upstream consumers own the transitive terminal-formatting major transitions. The reviewed pure-ESM and output changes cover ANSI detection/styling, emoji patterns, string width, and sisteransi. There are no direct imports of these transitive libraries from shipped or CI code. Both npm example packaging and the runtime suite exercise the parent tools. [ansi-regex](https://github.com/chalk/ansi-regex/releases) · [ansi-styles](https://github.com/chalk/ansi-styles/releases) · [emoji-regex](https://github.com/mathiasbynens/emoji-regex/releases) · [string-width](https://github.com/sindresorhus/string-width/releases) · [strip-ansi](https://github.com/chalk/strip-ansi/releases) · [sisteransi](https://www.npmjs.com/package/sisteransi)
- Both Playwright images use the registry digest for the locked Playwright 1.65.1 release. The workflow regression test checks the tag and digest in both jobs against the npm version. BuildKit’s canonical and fallback registry tags resolve to the same manifest digest. Betterleaks 1.10.1 ships the same configuration checksum and 203-rule catalog as the prior patch. [Playwright release notes](https://playwright.dev/docs/release-notes) · [Buildx release](https://github.com/docker/buildx/releases/tag/v0.39.1) · [Betterleaks release](https://github.com/betterleaks/betterleaks/releases/tag/v1.10.1)
