A further release-integrity defect is reproduced in the template's `scripts/publish-to-npm.mjs` and `version-and-commit.mjs`: `--should-pull` executes `git pull origin main` after validation. Another main writer can therefore replace the source/dependency tree immediately before publication. The version helper also rebases on an advanced main without validating the new source, or reports its remote version without adopting it.

Offline reproduction: https://github.com/link-foundation/sensitive-data-sanitizer/blob/issue-92-255abc3c67f8/experiments/issue-92/publication-race.py . Run `python experiments/issue-92/publication-race.py before` in the downstream checkout. It creates temporary local Git repositories, pushes a validated commit, advances remote main with different source, returns the publishing checkout to the validated commit, and executes the original pull. The final assertion fails because publication now sees `unvalidated` source. No network or registry write occurs; Git subprocesses are bounded to five seconds. The `after` mode passes and keeps the original source.

Workaround: rerun validation on current main and publish the checked-out validated tree; do not pull or rebase new source after validation. For partial-release recovery, verify registry/GitHub state and permit an existing version-only child only after validating its parent, changed paths, and package/lock content excluding versions.

Suggested code fix: reuse metadata attestation plus a pure manifest/lock version-only comparison. Fetch to verify the attested commit landed using `git merge-base --is-ancestor`, without changing the publishing checkout. Before adopting a remotely pushed version on rerun, attest it against the validated parent and reject source/dependency changes with instructions to rerun CI. Keep ordinary same-version self-healing and explicitly requested changeset PRs. Add real temporary-Git regressions for a newer source commit, local and remote version-only children, and dependency drift in an otherwise allowed metadata path.

Implementation and tests: https://github.com/link-foundation/sensitive-data-sanitizer/pull/93 (commit 254eb4b). This extends the metadata-integrity concern described above; it does not establish a server-side cause for the original push rejection.
