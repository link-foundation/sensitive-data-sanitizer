## Research and existing components

Primary sources checked during the audit:

- [GitHub workflow dependency/status semantics](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax): supports the skipped-needs diagnosis and explicit status conditions.
- [GitHub larger concurrency queues](https://github.blog/changelog/2026-05-07-github-actions-concurrency-groups-now-allow-larger-queues/): queue:max is supported; retain the template's narrowly scoped actionlint schema exception.
- [CodeQL action](https://github.com/github/codeql-action) and [SARIF support](https://docs.github.com/en/code-security/reference/code-scanning/sarif-files/sarif-support): reuse CodeQL analysis and add a small local result gate, rather than another scanner service.
- [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/): retain OIDC, registry verification and optional explicitly configured fallback credentials.
- [npm install script policy](https://docs.npmjs.com/cli/v11/commands/npm-install-scripts/): review hooks per exact allowed package version; deny unused native helpers.
- [ESLint version support](https://eslint.org/version-support/): ESLint 9 reached end of maintenance on 2026-08-06; upgrade the shared dependency graph.
- [RE2 README and supported syntax](https://github.com/google/re2): linear matching is useful and RE2 wrappers already exist in this package, but replacing all native detectors would lose required backreferences/lookaround. Use a linear scanner for the observed problematic credential format.
- [Official artifact toolkit](https://github.com/actions/toolkit/tree/main/packages/artifact), @zip.js/zip.js, Changesets, command-stream and lino-arguments: reuse pinned existing components and the template's tested adapters; do not introduce a second release system.
- [GitHub status incident](https://www.githubstatus.com/incidents/smtdswd1h2w4) concerns November 4. It is not evidence that the November 5 push failed for the same cause. A server-internal incident cannot be established from this repository's logs.

Additional primary sources:

- [minimatch advisory](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249) and [glob advisory](https://github.com/isaacs/node-glob/security/advisories/GHSA-3g3m-2fjr-6pw4): patched versions and affected ranges inform the narrow overrides.
- [Dependency Review v5](https://github.com/actions/dependency-review-action): advisory enforcement and contextual repository scorecards are separate controls.
- [actionlint issue 711](https://github.com/rhysd/actionlint/issues/711) and [parser PR 732](https://github.com/rhysd/actionlint/pull/732): known local-action syntax-support gap. Keep the template's documented compatibility exception rather than disabling workflow lint.
- [Deno parallel execution](https://docs.deno.com/runtime/reference/cli/test/#parallel-execution): files execute in separate workers; default parallelism follows available CPUs. Precompilation does not remove execution or subprocess costs.
- [npm audit exit-code semantics](https://docs.npmjs.com/cli/v11/commands/npm-audit/#exit-code): distinguish advisory exit 1 from execution failure, and require matching evidence.
- [git pull](https://git-scm.com/docs/git-pull) integrates fetched changes into the current checkout; [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/) preserves the committed dependency tree. Avoid post-validation source pulls in publication.

## Evidence limits and diagnostics

This PR cannot observe GitHub's server internals, perform a live npm release from a feature branch, or prove that every future third-party outage will recover. Bounded mock regressions establish the client behavior for the exact recorded response. CI tests read-only paths and the complete platform matrix; release/Pages API tests exercise permanent errors, transient retries, lost responses, malformed data and budget exhaustion without mutating main.

`CI_SCRIPTS_DEBUG=1` adds push attempt/classification diagnostics; `PIPELINE_STATUS_VERBOSE=1` and existing preflight/preview verbose modes retain more context when required. Defaults remain off. Final current-commit verification is recorded in `VERIFICATION.md` and run metadata, separately from historical results.
