# Multilingual scanner and competitor workflow audit

[Issue 220](https://github.com/link-foundation/sensitive-data-sanitizer/issues/220) asks for a current competitor comparison, English, Russian, Chinese and Hindi support, implementation of the common and popular workflows, and adoption of the associative stack wherever it fits. The issue had no comments or GitHub sub-issues when reviewed on November 20, 2026. The prepared [PR 221](https://github.com/link-foundation/sensitive-data-sanitizer/pull/221) had no conversation comments, inline comments or reviews at intake.

The [source and measurements record](EVIDENCE.md) captures the competitor versions, public requests and reproducible results. The broader [issue 128 comparison](../issue-128/README.md) and [issue 146 audit](../issue-146/README.md) establish the baseline for the other scanner families.

## Why these workflows take priority

A fixed line-number fingerprint is cheap to compute but turns formatting changes into review work. A whole-file digest moves the same problem to any file edit. A keyed per-finding fingerprint uses more explicit setup and must be regenerated when the key changes. It keeps the scan useful across edits and reports a duplicate even when its text matches one already recorded. It counts instances of each fingerprint. If an old occurrence is deleted and the same value appears elsewhere in that same file, the count stays the same. Transfer across renames or between archive members requires a fresh review.

The staged hook checks the complete current content of changed index blobs. This also exposes previously existing text in a modified file. A deliberate baseline can review that noise without switching to a diff-only detector that would miss unchanged context. The gitignore mode preserves tracked files and follows Git's ignore hierarchy for untracked files. Default explicit file and directory scans continue to include paths selected by the caller. These behaviors are independent of the history selectors, which filter commit selection and their reachable objects.

For PII, contextual recognition keeps log vocabulary useful. The fixture corpus demonstrates the precision tradeoff for unclued numbers, public IPs, dates, labels, and identifiers. The documents profile, exact known values, declarative detector policy and local NER afford different recall and false-positive costs. For credentials, checksums increase confidence while truncated values remain eligible, and explicit provider verification is independent of offline scanning. See the [older per-case analysis](../../comparison/measured-results.md) and [verification contract](../../VERIFICATION.md).

## Associative stack

Reviewed the [Formal AI stack map](https://github.com/link-assistant/formal-ai/blob/main/docs/associative-tech-stack.md) as retrieved on November 20, 2026 (Git blob `8c600c224db0942873c5d79be3018d613233da35`).

| Components                                                    | How they fit                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `links-notation`, `lino-objects-codec`                        | Use the notation parser for bounds and the codec for readable first-party artifacts. Keep the pinned codec compatible with the supported Node 22 floor. Keep the previous restore-map reader, including its UTF-16-preserving envelope.                                                                                                                                                      |
| `lino-i18n`, `lino-arguments`                                 | Load locale catalogs and resolve an explicitly supplied policy/locale from the environment. Positional parsing and compatibility flags stay in the existing CLI. An implicit policy found in the scanned project could change its review rules.                                                                                                                                              |
| `command-stream`                                              | Use the argument-vector runner for Git index and worktree plumbing, building on the existing repository dependency.                                                                                                                                                                                                                                                                          |
| `meta-language`, `transformer`                                | A grammar or rule transformation layer could model future structured input. The current scanner projects exact decoded spans into the caller's original text and verifies residuals. Switching those paths requires equivalent offsets, field handling, lossless text and bounded parsing. The upstream object codec already provides the required structured representation for this issue. |
| `link-cli`, `doublets-rs`, `doublets-web`, link query dialect | Useful when maintaining a persistent relationship store. The portable file baseline needs exact multiset lookup and the published report needs a serial form. Neither workflow needs a resident store or a new installer requirement.                                                                                                                                                        |
| `web-search`, `web-capture`                                   | Relevant to research and sourcing. Scanning a local path does not need to send source text to a network service.                                                                                                                                                                                                                                                                             |
| `link-calculator`, `relative-meta-logic`, `meta-theory`       | Arithmetic, inference and model semantics do not participate in fingerprint generation or span detection. Existing native implementations provide the deterministic operations needed here.                                                                                                                                                                                                  |
| Agent CLI and Hive Mind                                       | Development and orchestration components. The published scanner has no dependency on an agent or hosted runner.                                                                                                                                                                                                                                                                              |

## Remaining measurable limits

This audit improves the locally testable workflow and records the results at the tested versions. The expanded matrix still shows differences. Full provider-specific parity and accuracy across every competitor and input is unverified. The pinned provider catalogs and optional scanner/NER adapters cover different subsets. The implementation handles local ZIP, TAR and GZIP and scans their text members. PDF/Office extraction, OCR and managed cloud integrations retain the limits in the [deployment comparison](../../comparison/deployment.md). The original test collection records misses and over-redaction and remains a regression reference.
