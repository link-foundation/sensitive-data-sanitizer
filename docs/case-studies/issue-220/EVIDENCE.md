## Reproduction

The [synthetic CLI comparison](../../../experiments/issue-220/compare-gitleaks.mjs) executes the default local file scanner and the published Gitleaks binary in one temporary directory. It records detection per file and publishes only fixture identifiers and outcome booleans. Both tools run with built-in policy and local file access. The Gitleaks report is fully redacted and stays in the temporary directory.

Download the appropriate archive and checksum list from [Gitleaks 8.30.1](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1) and verify the archive before running the experiment. The checked Linux x64 archive was verified with the release SHA-256 list.

```sh
node experiments/issue-220/compare-gitleaks.mjs /path/to/gitleaks
```

| Fixture group                                                               |      Cases | Sanitizer detected | Gitleaks detected |
| --------------------------------------------------------------------------- | ---------: | -----------------: | ----------------: |
| Synthetic provider token and freshly generated complete PEM                 | 2 positive |                  2 |                 2 |
| Labeled credentials in English, Russian, Chinese and Hindi                  | 4 positive |                  4 |                 0 |
| Labeled names in English, Russian, Chinese and Hindi, plus an email address | 5 positive |                  5 |                 0 |
| URI credentials and deliberately short private-key body                     | 2 positive |                  2 |                 0 |
| Ordinary prose in four languages and one credential template                | 5 negative |                  0 |                 0 |

The labeled and intentionally short cases test workflows claimed by the sanitizer. Gitleaks is designed primarily for credential discovery in code, and its generic rule uses filters such as minimum length and entropy. The corpus is small and purpose-built. The counts do not establish superiority across provider catalogs, arbitrary private prose, missed variants or runtime performance.

To rerun the broader native redaction cross-check, use the following command for each issue 128 corpus. Reports include fixture text and should stay local. Only counts are reproduced below.

```sh
for corpus in open-source-secrets open-source-pii closed-source; do
  node experiments/issue-128/probe-cases.mjs "docs/case-studies/issue-128/research/${corpus}-cases.json" --json | jq .summary
done
```

These are sanitizer redaction results on competitors' documented cases, distinct from executing those competitors. A miss means a declared sensitive substring survived. An over-redaction means a negative case changed. Some skipped cases depend on binary data or custom caller policy. The [earlier issue 128 analysis](../../comparison/measured-results.md) classifies the principal misses and over-redactions. The [independent binary benchmark](../../../experiments/benchmark/README.md) gives another historical comparison using a separate corpus, tools and runtime.
