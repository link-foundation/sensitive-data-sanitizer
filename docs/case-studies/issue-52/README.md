## Root causes and primary-source research

The shared `authorizationRange` guarded `[REDACTED]` only at the start of the header value. Its optional scheme then allowed the token's opening bracket but excluded its closing bracket. Its negated character class also admitted NUL and other non-whitespace C0 controls. Both `detectCredentials` and `detectAuthorization` use this function, so a shared correction covers both paths and their decoded projections.

[RFC 6750 section 2.1](https://www.rfc-editor.org/rfc/rfc6750.html#section-2.1) defines a restricted Bearer token alphabet. This supports treating controls as boundaries. Inference: strictly imposing that alphabet on this sanitizer would miss malformed logged credentials and other supported schemes, so preserve broad token detection and add structural boundary handling instead. A complete HTTP parser would add dependencies and would not handle shell commands, escaped transcript strings and malformed headers by itself.

[re2-wasm's wrapper](https://github.com/google/re2-wasm/blob/main/src/re2.ts) passes the complete JavaScript subject to its WASM wrapper on each `exec`; its public API offers no retained subject handle. Repeated `exec` therefore repeats marshalling even though RE2's search engine is safe. [RE2JS](https://github.com/le0pard/re2js) already provides reusable matching in JavaScript and original UTF-16 indices. Its installed 2.9.0 exposes `matchAll`, already used by this repository's large-view fallback. Reusing it avoids an additional dependency and native build requirements. [node-re2](https://github.com/uhop/node-re2) is another existing safe regex binding, but replacing the cross-runtime dependency would expand packaging scope. Keyword windows are already used where rule bounds are proven; applying arbitrary windows to every rule risks truncating unbounded secrets and changing anchors. A retained-input WASM API would require an upstream change. The bounded adaptive fallback solves the repeated copies for all catalog rules locally.

[fast-redact](https://github.com/davidmarkclements/fast-redact) is an existing object-path redactor. Inference: it can redact a structured Authorization field when the caller already knows its path, but cannot replace transcript substring detection, byte-preserving log handling or the catalog scanner. No extra dependency is needed for either correction.

## Verification

Before implementation, issue 50's suite failed 17 of 21 tests, reproducing the four report rows and their Proxy-Authorization equivalents. Issue 51's deterministic WASM-copy test also failed. The same finite scanner harness runs against the original `9e21525` source snapshot and the corrected module:

| Input                         | Original whole-view WASM calls | Corrected calls | Original scanner time | Corrected scanner time |
| ----------------------------- | -----------------------------: | --------------: | --------------------: | ---------------------: |
| 32 KiB, 800 distinct tokens   |                            804 |              11 |                1.25 s |                 0.17 s |
| 64 KiB, 1,599 distinct tokens |                          1,606 |              14 |                4.09 s |                 0.16 s |

These totals include other eligible catalog rules; the bound is eight matching WASM calls per rule/view, rather than a global eight-call limit. Timings are local measurements and vary with warm-up and system load. The deterministic copy bound protects the complexity independently of timing.

With 256 KiB of distinct space-separated synthetic tokens, native verified sanitization completes in 0.39 s, the default required scanner union in 1.16 s, and streaming in 1.16 s. Every space-separated token is replaced with exact separator preservation. Newline-only base64-alphabet runs above the existing decoding limit retain the existing fail-closed encoded-container behavior (`[REDACTED]` plus the trailing newline); the benchmark checks that output explicitly rather than changing unrelated policy. The newline case completes in 0.99 s. The automated 256 KiB regression uses an eight-second budget to allow cold cross-platform CI runners, together with a deterministic copy-count assertion.

Focused verification passed all 97 selected tests. The final regressions cover matching delimiters, all C0 controls and DEL, exact binary CLI output, repeated sanitization, shell/JSON escape depths, captures, entropy, Unicode at the engine transition, all vendored text-pattern compilation and required scanner union behavior. Existing long-record tests still verify complete detection above the fixed WASM heap.

Complete local suites pass: Node 1,496 tests (221 s), Bun 1,496 tests (151 s), Deno 1,351 tests plus eight steps (104 s), with zero failures. The 256 KiB regression completes in 1.44 s in the full Node suite, 0.72 s in Bun and approximately 1 s in Deno. Node uses a 256 MiB heap and one test process; the suites run sequentially. Deno's npm directory changes are followed by `npm ci` before returning to Node tooling.

The cold CLI reproduction sanitizes 262,400 bytes containing 6,400 distinct credentials in 3.33 s without streaming and 3.21 s with `--stream`, including process startup and the required scanners. Both outputs match exactly. Run `node --max-old-space-size=128 experiments/issue-52/cli-throughput.mjs`; each child receives a 256 MiB heap and 4 MiB stack. Reusable experiment: `node --max-old-space-size=256 --stack-size=4096 experiments/issue-52/dense-tokens.mjs 256`. Large outputs are preserved locally under `ci-logs/`; stress inputs and heaps are finite.

Local lint, formatting, duplication, secrets, module syntax, required documentation, line limits, version guard and patch-changeset validation pass. The existing Codex/Claude session corpus passes with both one and four workers and zero residual secrets.
