## Research and alternatives

- [petrovich-js](https://www.jsdelivr.com/package/npm/petrovich-js?tab=files) and [lvovich](https://jsdelivr.com/package/npm/lvovich?tab=files) are MIT-licensed JavaScript name decliners. They inflect names into a known case but do not recognize forms in text. They would add a runtime dependency to a library that keeps finite, reviewable vocabularies, and fake output needs only the words this repository generates. The chosen `src/russian-declension.js` covers exactly those words. A caller wanting broader declension could use these libraries to prepare `knownPersonal` values.
- [pymorphy3](https://github.com/no-plagiarism/pymorphy3) offers full morphological analysis but needs Python and dictionaries. It stays an option for caller-side detectors, as in [issue 65](../issue-65/README.md).
- [Faker localization](https://fakerjs.dev/guide/localization) already supplies gendered Russian name parts, so no new generator was needed. Its Russian company names are generated compounds such as `ООО МайкопТрейд`, and its city list includes annotated entries such as `Зеленогорск (Ленин.)`. Neither can be declined reliably with finite rules, so organization, school and location names come from a short authored list.
- `ё`/`е` folding is standard practice in Russian search: see [Meilisearch's charabia](https://github.junw03049948.workers.dev/meilisearch/charabia/pull/296), [GLib's discussion](https://gitlab.gnome.org/GNOME/glib/-/issues/3129) and [inkhaven's text module](https://docs.rs/crate/inkhaven/1.3.1/source/src/text.rs). Folding applies only to matching and identity, so the exact surface still restores.
- CV parsers treat the date range as the anchor of an employment entry ([Lido](https://www.lido.app/blog/resume-ocr), [RChilli](https://help.rchilli.com/hc/en-us/articles/4404204581145-How-Employment-Dates-Are-Extracted-from-a-Resume)), which matches the proposal in #70. An NER model such as those behind [Presidio](https://presidio.dataprivacystack.org/anonymizer/) would find more shapes but would need a model download, which the library avoids.
- A `fakeValues` map, as floated in #68, is not possible as named: `fakeValues` is already an array of reviewed identity values to retain. The hook is therefore called `pools`. It takes arrays rather than a callback, so transformation options stay plain, validated data.

## Limitations

- The 236-document corpus from #69 and #70 is private and was not available, so its aggregate numbers were not re-measured. The tests cover every published row and shape instead, so the actual corpus miss rate after this change is unknown.
- The #70 table also reports EDUCATION (14 of 15 missed), PERSON and LOCATION misses. No shapes, expected outputs or acceptance rows were published for them, so they were not changed.
- A source preposition stays as written, so the fake can read `о Осипове` or `со Потаповой`. Replacing text outside the finding would break exact restore, and #67 accepts the same cosmetic effect.
- Lines with more fields (`Title, Employer, City (dates)`) and titles containing a comma are not targeted, so such an employer can remain. Date-anchored prose of the same shape can be flagged.
- In fake mode, autodetected mentions that occur only in oblique forms stay separate entities, as in placeholder mode. Listed `knownPersonal` values do not have this limitation.
- Generated entity names are plausible and can coincide with real entities that the text does not mention.

## Reproduction and validation

`node experiments/issue-71/reproduce.mjs` prints every row reported in #67–#70. The regression tests are in the four test files named above, for example `node --test --test-timeout=30000 tests/sanitizer-known-forms.test.js`. Full platform and runtime suites run in the PR's CI matrix.
