## Research and alternatives

- [Presidio anonymizer](https://presidio.dataprivacystack.org/anonymizer/) provides extensible operators and overlap handling. Existing repository adapters already allow Presidio; adding a Python service for these deterministic matching fixes would add deployment requirements.
- [pymorphy3](https://github.com/no-plagiarism/pymorphy3) offers Russian/Ukrainian morphological analysis with dictionaries. It is an option for a caller-side detector; the chosen core approach uses bounded, explicit ending alternatives anchored to caller-confirmed entities, avoiding Python/dictionary downloads and broad stemming of unknown prose.
- [Faker localization](https://fakerjs.dev/guide/localization) and [person API](https://fakerjs.dev/api/person) already provide locale/gender-specific first, last and middle names. Reuse this installed dependency and fix role inference rather than add another generator.
- [GeoNames download data](https://download.geonames.org/export/dump/) offers cities15000 with attribution/licensing obligations. A finite authored expansion and contextual unknown-city rules cover this issue without importing a worldwide dataset. Vocabulary remains deliberately bounded and offline.

Implementation order: shared known-value boundaries/morphology and selection; placeholder namespace and identity linking; document entities; credential prose and irreversibility reporting; fake roles; regression tests/docs/release fragment; focused local validation and full CI review. Existing debug callbacks remain off by default and provide value-free detection/residual events for tracing.

### Intel execution: large fixtures and suite partitioning

The Intel jobs acquired runners and desktop packaging succeeded, including the `out/mac-arm64` artifact. Run [41874186510](https://github.com/link-foundation/sensitive-data-sanitizer/actions/runs/41874186510) then exposed actual test execution costs: Node passed 1,624 assertions but cancelled the seven-megabyte JSONL and >10 MiB publication cases at 30 seconds (`restart2-macos-node.log`, lines 2336–2341). A finite 5.4-million-character probe in `experiments/issue-65/profile-scans.mjs` with a 512 MiB Node heap showed repeated keyword and regular-expression scans dominating ordinary-word padding. The large streaming fixtures now retain their >7 MiB records, >10 MiB file, multiple batches, real credential, worker transport and private-publication assertions while using mostly whitespace padding. JSONL also asserts the entire ordinary field survives unchanged. This removes redundant word/line processing without reducing input-size coverage or changing production detection.

The complete macOS suite is deterministically partitioned into three jobs per runtime; Linux and Windows still run complete suites. `scripts/run-test-shard.mjs` selects sorted test files by index modulo shard count, propagates runtime failures, and retains Node/Bun's 30-second per-test limits. Regression tests verify that shard union covers every test exactly once, directory order does not matter, invalid selections fail, and runtime arguments preserve limits. The existing 300/200/100-second suite budgets and 15-minute job backstops are unchanged. All partitions are included in the mandatory pipeline gate; there are no missing-secret skips or manual actions.

The first partitioned run exposed one stale workflow-policy assertion: `workflow-reliability.test.js` expected the former concurrency key without a shard suffix (Linux Node log line 2342). It now requires the shard suffix so parallel groups cannot cancel each other. The macOS Deno group containing that assertion finished all other checks within 66 seconds of its unchanged 100-second budget.

### Remaining Bun deadlines: bounded credentials and scan fast paths

Current-head run [41876692215](https://github.com/link-foundation/sensitive-data-sanitizer/actions/runs/41876692215) exposed two further per-test deadlines: the macOS Bun oversized Gitleaks record took 34.4 seconds (`final-macos-bun2.log`, line 690), and Windows Bun's two-record JSONL test took 34.9 seconds (`final-windows-bun.log`, line 1680). Successful cleanup steps did not mean those test steps passed; each test-step conclusion was checked separately while GitHub was still updating job statuses.

The bounded experiment `experiments/issue-65/profile-large-engines.mjs` reproduces the original 1.12-million-character synthetic credential with a 512 MiB Node heap. Its generic-key scan alone took about 12.8 seconds. The CI fixture now retains a >10 MiB record and a complete 4,096-character credential, still well beyond the 384-character initial detection window. The original extreme credential remains reproducible in the experiment. A trial removing RE2JS's boolean preflight made nonmatching capture searches slower and was discarded.

Production scanning also avoids repeated character-by-character keyword Map lookups over irrelevant padding, using a native literal-starter search only when no prefix is active. ASCII detection views bypass unnecessary Unicode normalization/digit-string construction; ANSI and JSON-escape handling still precedes this shortcut. Keyword equivalence tests cover overlapping prefixes, literal metacharacters, Unicode starters and long padding; existing representation tests cover normalization and source offsets. No credential rule or default scanner is disabled.

Local Bun verification passed all 100 checks across keyword, representation, Gitleaks and JSONL streaming suites: the oversized Gitleaks assertion took 0.69 seconds and the two-record JSONL assertion took 14.6 seconds, within the unchanged 30-second limit. A finite single-record Node comparison improved from 8.94 to 7.16 seconds. Full current-commit CI remains the completion requirement.

Windows Bun on `2be3282` still took 41.7 seconds for the large JSONL assertion (`head-windows-bun.log`, line 1680), although its large Gitleaks case now passed in 0.40 seconds and macOS Bun's group passed completely. Local timings alone did not predict Windows scanning cost. A multibyte-padding trial was slower and discarded. The record/whole-input-limit fixture now puts its >7 MiB padding in valid JSON whitespace around an ordinary output field and an automatically detected password. Both large records still cross worker transport; total input still exceeds the whole-input limit, exact output-field preservation remains asserted, and no scanner is disabled. This isolates byte-limit/transport coverage from repeated detection over millions of padding characters. Local Bun passes the assertion in 5.3 seconds. The original large string-value workload is retained as the finite `jsonl` mode of `profile-large-engines.mjs` for targeted performance investigation.
