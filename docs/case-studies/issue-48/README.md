## Root causes and experiments

The old native Authorization capture excluded quotes/commas but allowed spaces. Context selected line mode for unquoted colon fields and missed single-quote boundaries. Their overlapping findings therefore erased the rest of a log line. A shared header range fixes both. Reproducing tests were run before the fix and failed on trailing-text preservation.

Environment discovery selected solely by a broad credential-name regex. AUTH_TRANSPORT is configuration even though AUTH matches. Filtering value shape would miss real passwords such as short words, URLs or paths. Configuration suffixes are excluded only during automatic discovery; explicitly selected values remain authoritative. The reproducing test returned seven ordinary configuration values before the fix.

File workers originally had one wall-clock timer for the complete file, unlike stdin streams. Progress messages now renew that timer only after verified processing/output, with the same finite default per interval. Errors/timeouts still terminate workers and remove private staging. Two-pass discovery reports completed batches too. NUL rejection was duplicated between file decoding and plain/JSONL streams. Only plain-text paths permit the new explicit opt-in.

The ordinary 2 MiB baseline took 1.67 seconds (1.20 MiB/s), with 0.87 seconds for module import. Profiling the escaped corpus found most CPU samples in the bounded JSON-string regex. On malformed escaped log fragments it restarted at many quotes and repeatedly searched up to 8192 units. The replacement scanner preserves the old regex's recovery behavior and unit bound, including escaped openings, CR/LF and oversized candidates. Differential tests compare 1000 seeded malformed inputs plus boundary controls against the original regex. The original escaped baseline also hit ERR_RESIDUAL because its header reference boundary did not accept an enclosing escape; the header fix resolves that independently.

The reported four-second startup was not reproduced on this container: the baseline module import was already under one second. Fake-name indexing is now deferred until fake names are requested, retaining synchronous APIs and deterministic results. Runtime and hardware affect absolute timings; the reusable benchmark separates import from processing.

On the final Node 26 run, ordinary 2 MiB throughput improved from 1.20 to 1.43 MiB/s (1.67 to 1.40 seconds), with import time falling from 0.87 to 0.59 seconds. Escaped 2 MiB processing fell from 13.61 seconds after the header correctness fix alone to 3.55 seconds with the linear scanner (0.56 MiB/s). Peak RSS was approximately 136 MiB for ordinary input and 158 MiB for escaped input. Both benchmark outputs preserve their exact input byte counts.

A finite keyword experiment compared the existing Aho–Corasick matcher with per-keyword String.includes. The existing matcher won (445 ms versus 1141 ms over five 2 MiB scans); it is retained. This avoids adopting an unmeasured alternative.

Reusable scripts live under experiments/issue-48; downloaded upstream issue/reproduction snapshots and raw CPU/CI logs are local investigation data. Experiments use finite 1–80 MiB inputs and Node heap/stack limits. Runtime suites run sequentially under the shared container memory budget.

## Online research and existing components

- [RFC 9110 authentication grammar](https://www.rfc-editor.org/rfc/rfc9110.html#section-11.2) distinguishes token68 credentials from parameterized schemes. The issue explicitly requests scheme/one-token boundaries for embedded log snippets; this is not a complete HTTP Digest parser. Generic credential labels and scanner rules remain active for parameter values.
- [Node stream documentation](https://nodejs.org/api/stream.html) explains backpressure and that highWaterMark is a threshold, not a strict memory limit. Existing explicit record/total limits and atomic file staging remain necessary.
- [Node worker resource limits](https://nodejs.org/api/worker_threads.html#workerresourcelimits) bound the JS engine, not every external/native allocation. Keep the worker heap and finite deadlines instead of removing isolation to bypass the bug.
- [fast-redact](https://github.com/davidmarkclements/fast-redact) efficiently redacts known object paths. It could help structured-only consumers, but cannot replace detection in arbitrary transcript text or malformed/escaped JSON while preserving this package's scanner union.
- [node-re2](https://github.com/uhop/node-re2) offers native linear-time matching, but its native addon/runtime restrictions would conflict with Node/Bun/Deno support. Existing re2-wasm/RE2JS remain in place; the measured quoted-candidate hotspot is handled with a bounded linear scanner.
- [Secretlint recommended preset](https://github.com/secretlint/secretlint/tree/master/packages/@secretlint/secretlint-rule-preset-recommend) provides existing credential coverage. Disabling it would change the safety contract; union detection is retained.
