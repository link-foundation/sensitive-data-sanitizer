# Competitor capabilities, integration and remaining work

Primary source review date: 2026-10-07. This is a capability/design comparison, not a measured ranking. A detector union can recover different engines' findings, but shared blind spots and false positives remain. Every selected engine must succeed, including final-output verification.

## Open source components

| Component / primary source                                                                                                                                                               | Algorithm or capability                                                                           | Decision in this PR                                                                                         | Acceptance criteria for broader support                                                                                       |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| [Secretlint](https://github.com/secretlint/secretlint), [recommended preset](https://github.com/secretlint/secretlint/tree/master/packages/@secretlint/secretlint-rule-preset-recommend) | Maintained service rules, plugin scanner API, source ranges                                       | Required pinned 13.0.7 runtime engine; exclude untrusted comment suppression and disable profiling          | Retain actual-rule regressions when updating; validate current provider fixtures                                              |
| [Gitleaks](https://github.com/gitleaks/gitleaks)                                                                                                                                         | Service regexes, entropy, configurable rules, encoded/archive options, Git/text scanning          | Optional required local stdin detector and report adapter; actual 8.30.1 run                                | Add independently tested archive/depth settings with original-source mapping before claiming archive coverage                 |
| [TruffleHog](https://github.com/trufflesecurity/trufflehog)                                                                                                                              | Provider detectors, decoders and optional credential verification; repository/filesystem sources  | Optional required filesystem detector, verification/updates disabled, private temp input; actual 3.99.0 run | Benchmark supported decoders/false positives; online validity checks require explicit application policy                      |
| [detect-secrets](https://github.com/Yelp/detect-secrets)                                                                                                                                 | Plugin regex/entropy detection, hashed baselines and human audit                                  | Baseline adapter redacts complete flagged lines; supplemental opt-in entropy heuristic                      | A live plugin bridge needs versioned fixtures, complete-report checks and residual invocation                                 |
| [git-secrets](https://github.com/awslabs/git-secrets)                                                                                                                                    | Git hooks, configurable prohibited/allowed patterns and AWS-oriented providers                    | Native credential formats/context and local history audit cover part of this domain                         | Do not interpret line allowlists as proof every credential on that line is safe; custom hook/provider integrations need tests |
| [Presidio](https://github.com/microsoft/presidio), [language configuration](https://presidio.dataprivacystack.org/tutorial/05_languages/)                                                | Regex/context/validation recognizers plus configurable NLP models; analyzer/anonymizer separation | Optional local Python analyzer bridge, Unicode codepoint adapter and real English model test                | Install/test each language/model separately; structured, image and advanced anonymizer transformations need separate profiles |
| [scrubadub](https://scrubadub.readthedocs.io/en/stable/)                                                                                                                                 | Extensible PII detectors/postprocessors, localization, optional name/address dependencies         | Native PII validation/known values and generic required detector contract                                   | Implement a bridge with locale-specific labeled fixtures; do not infer language coverage from installed package names         |
| [Betterleaks](https://github.com/betterleaks/betterleaks)                                                                                                                                | Gitleaks-related successor project with its own rules and scanning behavior                       | Researched current alternative; no claimed tested adapter compatibility                                     | Pin a release and validate its executable/report contract before substituting it                                              |
| [git-filter-repo](https://github.com/newren/git-filter-repo)                                                                                                                             | Reviewed rewriting of blobs, paths, messages and identity metadata                                | Separate history-remediation procedure; no automatic destructive rewrite                                    | Rehearse against a disposable clone and immutable backup, verify refs/snapshots, then coordinate remote cleanup               |

Native entropy is a small supplemental Shannon-entropy heuristic, not a port of every competitor plugin. Report compatibility also differs from running a detector: the detect-secrets adapter can consume a caller-created baseline, while the default pipeline actually runs Secretlint. Known dictionaries and bounded normalization/decoding complement these components rather than establish model equivalence.

## Proprietary services: documented features and explicit gaps

| Primary documentation                                                                                                                                                                                             | Documented capability                                                                                    | Supported interoperability                                                                | Remaining feature gap                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Google [infoTypes](https://docs.cloud.google.com/sensitive-data-protection/docs/infotypes-reference), [de-identification](https://docs.cloud.google.com/sensitive-data-protection/docs/deidentify-sensitive-data) | Many infoTypes, custom detection and structured/cryptographic transformations                            | Convert exact text-item byte ranges through `fromOffsetReport()`; discard quoted payloads | Proprietary recognizers, structured transformations, cryptographic pseudonymization, storage scans and image inspection are not reproduced |
| Azure [Analyze Text API](https://learn.microsoft.com/en-us/rest/api/language/analyze-text/analyze-text/analyze-text?view=rest-language-analyze-text-2026-05-01)                                                   | PII entity analysis/redaction, language/model options and configurable string index type                 | Request UTF-16 offsets, map offset/length and category to the explicit adapter contract   | No cloud client/upload, proprietary model parity or claimed support for every entity/language                                              |
| AWS [PII entities](https://docs.aws.amazon.com/comprehend/latest/APIReference/API_PiiEntity.html), [supported languages](https://docs.aws.amazon.com/comprehend/latest/dg/supported-languages.html)               | PII analysis with entity offsets/types; PII feature language support differs from other Comprehend tasks | Generic adapter after callers establish exact SDK/report offset semantics                 | No guessed offsets or assumption that all Comprehend languages have PII support; proprietary model is not reimplemented                    |
| GitGuardian [secrets engine](https://docs.gitguardian.com/secrets-detection/secrets-detection-engine), [API](https://api.gitguardian.com/docs)                                                                    | Provider-specific detection, contextual occurrences and service workflows                                | A required custom detector can map validated occurrences to exact original spans          | No automatic authenticated API calls, secret validity checks, incident management, or claimed proprietary detector parity                  |

Closed documentation does not disclose every algorithm or model. Supporting report offsets is concrete interoperability; it is not a claim to reproduce all documented transformations, consoles, storage backends or model quality. The package does not upload text to a cloud service.

## Benchmark plan for the market-wide aspiration

Before claiming comparative superiority, freeze versions/configuration and define a publishable corpus with no real credentials: labelled positives and negatives by service, language, context, encoding and truncation. Include public/private ambiguities and benign code/counters. Record recall, precision, complete-span leakage, output syntax preservation, failure behavior, wall time and peak resident memory separately. Evaluate held-out examples and independent reviewers' labels; do not count one fixture per prefix as population recall.

Run each competitor independently and the union on the identical corpus. For proprietary models, use explicitly approved test accounts/data and record the selected regions/models/API versions. Report uncertainty and unsupported features rather than substituting marketing service counts for measured quality. This PR's real binary/model checks establish operational integration only; they are not that independent benchmark.
